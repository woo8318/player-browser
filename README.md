# Player Browser

URL 입력으로 웹을 탐색하고, 동영상 제스처 컨트롤·광고 차단·SNI 우회·Chromecast 송출을 갖춘 안드로이드 브라우저입니다. WebView 기반 단일 액티비티 + Jetpack Compose UI.

## 주요 기능

### 브라우징
- **상하단 분리 레이아웃** — 상단: 주소창 + 즐겨찾기 + Cast + 메뉴, 하단: 뒤로/앞으로/새로고침/홈/탭 (Opera 스타일)
- **멀티탭** — 탭별 WebView 인스턴스, 세션 영속화 (탭 + 그룹 + 부모 관계 모두 SharedPreferences로 저장). 앱을 껐다 켜도 각 탭의 **뒤로/앞으로 히스토리**까지 유지해 뒤로가기가 방문한 페이지들을 되짚습니다
- **스와이프로 탭 전환 (Chrome/Opera 스타일)** — 상단 주소창 바 또는 하단 내비 바를 좌/우로 스와이프하면 인접 탭으로 전환 (스위처를 열 필요 없음). 좌 스와이프 → 다음 탭, 우 스와이프 → 이전 탭. 전환 시 콘텐츠가 가로로 슬라이드되는 애니메이션 + 짧은 햅틱. 단, 새 창(`window.open` / `target=_blank`)으로 열린 탭에서 우 스와이프하면 그 창을 띄운 부모 탭으로 복귀 (인접 탭 대신). 부모가 없으면 양 끝에서 멈춤(no-wrap)
- **검색어/URL 자동 인식** — URL이 아니면 Google 검색으로 폴백
- **즐겨찾기 / 방문 기록** — 방문한 URL은 즐겨찾기 목록에서 ✓ 표시
- **도메인 숫자가 바뀌어도 방문한 링크 표시 (설정 토글, 기본 켜짐)** — 사이트 주소 숫자가 바뀌면(newtoki123 → newtoki124) 브라우저 기본 방문 표시(`:visited`)는 주소가 달라져 전부 사라집니다. 방문 기록을 도메인 숫자와 무관하게 비교해서 예전에 열었던 글의 링크를 보라색으로 표시합니다(썸네일은 그대로). 무한 스크롤로 나중에 추가되는 링크와 방금 누른 링크도 반영. 페이지에는 방문 기록 주소가 아니라 해시만 넘겨 사이트가 기록을 읽어갈 수 없게 했습니다. 주소에 숫자가 없는 사이트(`163.com`처럼 숫자만 있는 이름 포함)는 기본 방문 표시를 그대로 사용
- **요소 숨기기 (영역 선택, v1.3.100)** — ⋮ 메뉴 → "요소 숨기기 (영역 선택)"을 누르면 페이지 위에 선택 화면이 뜹니다. 손가락으로 **영역을 끌면** 그 안에 들어오는 요소가, **탭하면** 그 요소가 선택되고(다시 탭하면 해제), 두 손가락으로는 페이지를 스크롤할 수 있습니다. 하단 바의 **넓게/좁게**로 선택을 바깥 상자/안쪽 상자로 옮기고 **숨기기**를 누르면 사라집니다. 숨긴 요소는 **그 사이트에서 계속 숨겨지고**(도메인 숫자가 바뀐 미러 주소 포함, 앱을 껐다 켜도 유지) 나중에 다시 생기는 같은 요소도 가려집니다. 방금 숨긴 것은 **되돌리기**, 예전에 숨긴 것은 ⋮ → "숨긴 요소 관리 (N)"에서 골라 해제하거나 모두 해제. 보안 확인(캡차) 화면에서는 동작하지 않습니다
- **링크 길게 누르기 → 요소 숨기기 (v1.3.101)** — 링크를 길게 눌러 뜨는 메뉴("새 탭에서 열기 / 백그라운드 탭으로 열기 / 링크 주소 복사")에 **"요소 숨기기"**가 추가됐습니다. 누르면 위의 선택 화면이 **손가락이 닿았던 요소가 이미 선택된 상태로** 열려, 하단 바의 넓게/좁게로 범위를 맞추고 숨기기를 누르면 됩니다(광고 링크·추천 배너처럼 링크로 덮인 영역을 영역을 끌 필요 없이 바로 지목). 나머지 규칙(사이트별 유지·관리·캡차 화면 제외)은 같습니다. **v1.3.102:** 이 경로는 손가락 아래의 **링크(`<a>`) 요소 자체**를 잡습니다 — 예전엔 탭 규칙(48px 미만이면 부모로 확대)이 그대로 걸려 한 줄짜리 링크를 누르면 목록 항목·카드 전체가 선택되곤 했습니다. 링크가 아닌 곳이면 종전 규칙입니다. **v1.3.103:** 선택 화면이 떠 있는 동안에도 **링크를 길게 누르면 그 링크(`<a>`) 요소만** 선택에 들어갑니다(링크가 아닌 곳을 길게 누르면 닿은 요소 그대로, 확대 없이). 선택 화면은 모든 터치를 가로채므로 브라우저의 링크 메뉴는 그 안에서 뜨지 않고, 이 길게 누르기가 그 자리를 대신합니다
- **새 창 링크 → 부모 탭 복귀 (Opera 스타일)** — `target="_blank"` / `window.open()`이 띄운 자식 탭에서 뒤로가기 누르면 자식 탭을 닫고 원래 부모 탭으로 복귀
- **링크를 항상 새 탭에서 열기 (설정 토글, 기본 꺼짐)** — 켜면 새 창/팝업 링크가 아니어도 페이지 안의 일반 링크 탭이 현재 탭을 바꾸지 않고 새 탭(현재 탭의 자식)에서 열림. 뒤로 가기를 하면 원래 탭으로 복귀. 주소창 입력·리다이렉트에는 영향 없음
- **링크 롱프레스 메뉴** — 페이지의 링크를 길게 누르면 "새 탭에서 열기 / 백그라운드 탭으로 열기 / 링크 주소 복사" 메뉴가 뜸. 전역 토글을 켜고 끌 필요 없이 원하는 링크만 새 탭에서 열 수 있음. "백그라운드 탭"은 현재 페이지에 머문 채 새 탭을 뒤에 쌓음 (탭이 열릴 때 페이지 제목을 미리 가져와 탭 목록에서 뭐가 열렸는지 바로 구분 가능)
- **탭 갤러리 (썸네일 미리보기, Opera/삼성인터넷 스타일)** — 탭 스위처가 각 탭을 실제 페이지 썸네일이 채워진 카드로 보여줌. 보던 탭은 스위처를 열거나 스와이프로 전환하는 순간 현재 화면이 캡처되어 카드에 반영됨 (아직 캡처되지 않은 탭은 도메인 플레이스홀더). 활성 탭은 강조 테두리/그림자로 구분
- **탭 그룹화** — 탭 스위처에서 색상 라벨이 붙는 그룹을 만들어 탭을 묶고, 그룹 단위로 일괄 닫기 / 이름 변경 / 해제. 그룹 섹션 헤더는 색상 칩 + 탭 개수 배지로 구분되어 보기 편함. 자식 탭은 부모의 그룹을 자동으로 상속
- **그룹 안에서 바로 새 탭** — 그룹 헤더의 ＋버튼을 누르면 그 그룹 소속으로 새 탭이 바로 열림 (전체에서 만들고 그룹으로 옮기는 번거로움 없음)
- **그룹 순서 변경** — 그룹 헤더를 길게 눌러 끌어서 원하는 위치(다른 그룹 헤더의 위/아래 절반)에 드롭하면 그룹 섹션이 통째로 이동. 헤더 우측 ⋮ 메뉴의 "위로 이동" / "아래로 이동"도 그대로 사용 가능 (변경된 순서는 영속화)
- **탭 멀티 선택 → 일괄 닫기 / 그룹 이동** — 탭 카드를 길게 누르면 선택 모드 진입, 상단 액션 바에서 전체 선택 / 그룹으로 이동 / 일괄 닫기
- **탭 카드 메뉴로 1탭 그룹 이동** — 탭 카드 우측 ⋮ 메뉴에서 "그룹으로 이동..." / "그룹에서 빼기" 로 단일 탭을 다른 그룹으로 옮기거나 그룹 밖으로 빼기 (멀티 선택 모드를 거치지 않고 바로 처리)
- **드래그로 탭 그룹 이동 · 탭 사이 재정렬** — 탭 카드를 길게 눌렀다가 그대로 끌어서 그룹 헤더나 그룹 영역에 드롭하면 그 그룹으로 이동, 다른 탭 위에 드롭하면 그 탭 앞/뒤(좌/우 절반)로 **탭 사이 삽입(재정렬)**, 드래그 중 나타나는 "그룹 없음" 섹션에 드롭하면 그룹에서 빼기. 손가락을 따라다니는 미리보기 배지와 삽입 위치 표시 바로 착지 지점을 안내. 멀티 선택 상태에서 끌면 선택된 탭 전체가 함께 이동하고, 화면 가장자리로 끌면 자동 스크롤 (스크롤로 원래 카드가 화면 밖으로 나가도 드래그가 끊기지 않음)
- **활성 탭으로 자동 스크롤** — 탭 스위처를 열면 지금 보고 있던 탭 위치로 자동 스크롤되어 목록이 길어도 바로 찾을 수 있음
- **외부 브라우저로 열기** — 메뉴에서 현재 URL을 시스템 브라우저로 전달
- **순정 WebView로 열기 (진단)** — ⋮ 메뉴에서 현재 페이지를 앱의 가로채기·스크립트 주입·네이티브 브리지·원격 디버깅이 전부 없는 맨 WebView 로 엽니다. "사람인지 확인"이 무한 반복될 때 그 원인이 이 앱의 코드인지 안드로이드 WebView 자체인지를 가르는 측정용이며, 결과는 설정 → 디버그 로그의 `BareWebView` 항목에 남습니다 (여기서 통과하면 받은 통과 쿠키는 돌아간 탭에서도 그대로 쓰입니다)
- **사이트 데이터 지우기** — ⋮ 메뉴에서 현재 사이트의 쿠키·캐시를 지우고 다시 엽니다. "사람인지 확인"이 무한 반복될 때 깨끗한 상태로 다시 시도할 수 있습니다 (로그인 세션도 함께 지워집니다)
- **브라우저 위장 토글** — 앱 내 WebView라는 표식(User-Agent, Sec-CH-UA, X-Requested-With 헤더, 자바스크립트 환경)을 한꺼번에 감춥니다. 끄면 손대지 않은 순정 WebView 그대로 동작하므로, 일부 사이트의 "사람인지 확인"이 무한 반복될 때 기본 상태와 비교해 볼 수 있습니다
- **자체 업데이트** — GitHub Releases에서 새 버전 감지 후 인앱 다운로드/설치 (앱이 `PackageInstaller` 로 직접 설치 — 다른 설치 앱으로 넘기지 않음)

### 동영상 제스처 (`<video>` 위에서 동작)
- **1손가락 좌/우 스와이프** — -10초 / +10초 시킹
- **사이드 인식 더블탭** — 좌측: -10초, 우측: +10초, 중앙: 재생/일시정지
- **드래그 시킹 (수평)** — 손가락 위치에 비례해 정밀 시킹
- **2손가락 좌/우 스와이프** — 이전 / 다음 `<video>` 요소로 전환
- **세로 드래그 (풀스크린)** — 좌측: 화면 밝기, 우측: 시스템 볼륨 (MX Player / VLC 스타일). 조절 중인 값을 화면 위 네이티브 HUD 로 표시 (v1.3.90 — 예전엔 풀스크린에서 표시가 전혀 안 보였음)
- **풀스크린 스와이프 (v1.3.90)** — 1손가락 좌/우: -10초 / +10초 (하단 컨트롤 영역은 사이트 스크러버를 위해 제외), 2손가락 좌/우: 이전 / 다음 영상. 결과("⏩ 10초" / "다음 영상" / "시킹할 영상 없음")를 화면에 표시
- **풀스크린 가장자리 무시 (v1.3.92)** — 화면 끝에서 시작한 스와이프(알림창 내리기 / 뒤로 / 홈)는 시스템 몫으로 두고 밝기·볼륨·시킹을 걸지 않음 (위아래 48dp, 좌우 24dp — 기기의 시스템 제스처 영역이 더 넓으면 그만큼)
- **풀스크린 카메라 구멍 영역까지 채움 (v1.3.93)** — 가로 풀스크린에서 카메라 쪽에 생기던 검은 띠(세로에선 위쪽 띠)를 없애 영상이 화면 끝까지 닿게 함. 16:9 영상을 더 긴 화면(S24 등)에서 볼 때 좌우에 남는 여백은 영상 비율 때문이라 그대로 (다른 브라우저와 같음)
- **풀스크린 영상 최대 크기 맞춤 (v1.3.94)** — 사이트 CSS 때문에 풀스크린에서도 영상이 작게 나오거나 잘려 보이면, 영상 비율을 지킨 채 화면에 들어가는 최대 크기로 다시 맞춤. **절대 잘라내지 않음** — 비율이 화면과 다르면 양쪽(또는 위아래)에 같은 폭의 여백이 남는 게 정상. 이미 제대로 나오는 사이트는 건드리지 않음
- **풀스크린 핀치 줌 (v1.3.96)** — 두 손가락을 벌리면 확대(최대 400%), 확대 중엔 한 손가락으로 화면 이동, **더블탭하면 원래 크기**로 복귀(풀스크린을 나가도 복귀). 기본은 언제나 잘림 없는 원래 크기이고 1배 아래로는 줄어들지 않음. 확대 비율은 화면에 "확대 N%" 로 표시. 확대 중에도 하단 컨트롤 영역 드래그는 사이트 스크러버로 감. 두 손가락을 옆으로 미는 영상 전환은 확대하지 않은 상태에서 종전대로 동작
- **풀스크린 가로/세로 자동 회전** — 영상 비율 감지로 결정
- **이어보기 (보던 곳부터 재생)** — 페이지별로 동영상 재생 위치를 기록해 두고, 다음에 같은 페이지를 방문하면 그 지점부터 자동 재생 (진입 시 토스트로 안내). 90초 이상 영상만 대상이고 시작·끝 근처는 제외, 끝까지 본 영상은 기록 삭제. 설정에서 토글 가능. **v1.3.106:** 다른 도메인의 플레이어 iframe 안 영상도 위치를 저장·복원합니다 — 그 프레임이 앱 브리지를 못 봐도 부모 페이지를 거쳐 저장하므로, 보안 확인을 거친 사이트(tvroom35 등)에서 새로고침해도 보던 곳부터 이어집니다(v1.3.105 의 iframe 제스처 주입과 짝). 새로고침 직전 마지막 5초 이내 구간은 유실될 수 있습니다
- **iframe / cross-origin 영상도 지원** — `IframeScriptInjector`가 자식 프레임 HTML에 제스처 JS 주입
- **무한 로딩 자동 풀기 (v1.3.107)** — 사이트 플레이어가 조각 하나를 기다리며 로딩만 돌 때, 진행바를 손으로 옮기면 풀리던 것을 앱이 대신 합니다. 재생 중인데 8초 동안 시간이 안 움직이면 앞으로 조금 탐색해 다시 요청하고(`[stall:net #1]`처럼 코드 표시, 최대 3회, 그 뒤 `[stall:giveup]`), 버퍼는 있는데 멈춘 경우는 0.1초만 밀어 다시 돌립니다. 코드가 어떤 것이 뜨는지 알려 주시면 원인(네트워크/광고 차단/플레이어)을 좁힐 수 있습니다
- **보안 확인을 거친 사이트의 iframe 플레이어에서도 제스처 (v1.3.105)** — "사람인지 확인"(Cloudflare)을 내려준 사이트는 통과 쿠키를 지키려고 앱이 iframe 을 다시 받지 않는데, 그 탓에 다른 도메인의 플레이어 iframe 안 영상에는 제스처 JS 가 없어 더블탭·스와이프 ±10초가 아무 반응이 없었다(tvroom35 등). 이제 네트워크를 건드리지 않고 WebView 가 문서를 만들 때 자식 프레임에 직접 싣는다(보안 확인 화면·캡차 위젯 프레임은 제외). 보안 확인을 통과한 직후 처음 뜬 페이지에서 제스처·광고 차단 등이 통째로 빠지던 문제와, iframe 플레이어 풀스크린에서 옆으로 밀면 수 분씩 튀던 문제도 함께 고쳤다(풀스크린에서도 더블탭 ±10초는 그대로)

### 내장 동영상 플레이어 (Media3 / ExoPlayer)
- **플레이어로 재생** — 페이지에서 추출된 스트림(`.m3u8` / `.mp4` / `.webm`)을 **앱 내장 네이티브 플레이어**로 띄움. 사이트 플레이어 위 오버레이/레이아웃과의 제스처 충돌 없이 깔끔하게 재생/제어
- **화면 내 재생 버튼 (v1.3.45)** — 재생 가능한 스트림이 감지되면 화면 우하단에 "▶ 플레이어로 재생" 버튼이 자동으로 떠서 메뉴를 열지 않고 바로 실행. 필요 없으면 × 로 닫을 수 있고 페이지를 옮기면 다시 표시(상단 ⋮ 메뉴 항목도 그대로 유지)
- **영상 롱프레스 → 메뉴로 외부 플레이어 연결 (v1.3.50, v1.3.51)** — 한 페이지에 영상이 여러 개일 때 화면 버튼만으로는 어떤 영상이 열리는지 알 수 없어서, 원하는 `<video>`를 **길게 누르면** 그 영상에 대한 메뉴("외부 플레이어로 재생 / 여기서 우리 플레이어로 재생 / 다운로드 (다 받고 보기) / 받으면서 바로 보기 / Chromecast로 재생 / 영상 주소 복사")가 떠서 선택. 그 영상의 실제 소스를 읽어 재생하고, `blob:`/MSE라 URL이 없으면 감지된 네트워크 스트림으로 폴백. 재생할 스트림을 못 찾으면 메뉴 대신 안내만 뜸(v1.3.51 — 확인 없이 바로 실행되던 동작을 메뉴로 바꿈)
- **영상 재생 방식 설정 — 사이트 영상을 그 자리에서 우리 플레이어로 교체 (v1.3.89)** — 설정 → "영상 재생 방식"에서 **사이트 플레이어(기본)** / **우리 플레이어로 자동 교체** 를 고른다. 자동 교체를 켜면 페이지 영상이 재생되고 스트림이 잡히는 순간, 페이지의 `<video>` 영역 위에 **정확히 같은 크기로** 우리 Media3 플레이어가 덮여 그 자리에서 이어 재생된다(사이트 영상은 일시정지·음소거로 뒤에 남음). 영상 아래 컨트롤 바(−10초 / 재생·정지 / +10초 / 전체화면 / ×)는 영상 화면과 겹치지 않고, × 를 누르면 사이트 플레이어로 되돌아간다(정지 상태). 전체화면은 기존 전용 플레이어를 같은 위치부터 연다. 설정을 끈 채로도 영상 롱프레스 메뉴의 "여기서 우리 플레이어로 재생"으로 영상 하나만 수동 교체 가능. **한계:** `blob:`/MSE/DRM 영상은 스트림 URL이 없어 조용히 사이트 플레이어 그대로 두고, 오버레이 아래 사이트 자체 컨트롤·자막·팝업은 가려지며, 스크롤 시 약 한 프레임 늦게 따라온다
- **"여기서 우리 플레이어로 재생" 실패 이유 표시 (v1.3.95)** — 수동 교체가 안 될 때 아무 반응 없이 끝나던 것을, 실패한 지점마다 **대괄호 코드가 붙은 안내**로 알려준다(예: `[none]` 길게 누른 영상을 못 찾음, `[tiny]` 영상 영역이 너무 작음, `[broadcast]` 영상 프레임이 응답 없음, `[hidden]` 사이트가 영상 영역을 숨겨 되돌림). 성공하면 "우리 플레이어로 교체했어요"가 뜬다. 로그 없이도 코드 하나로 원인을 좁히기 위한 판
- **우리 플레이어가 사이트 플레이어로 되돌아가는 이유 표시 (v1.3.97)** — 교체된 뒤 다시 원래대로 돌아가는 경로마다 **대괄호 코드**가 붙은 안내가 뜬다(자동 교체도 포함): `[error:코드 http=상태]` 우리 플레이어 재생 실패(스트림 호스트 함께 표시), `[hidden]` 사이트가 영상 영역을 숨김, `[gone]` 영상이 페이지에서 사라짐, `[nav]` 페이지가 바뀜, `[tabswitch]` 다른 탭으로 옮김, `[notrack]` 교체 뒤 1.5초 동안 페이지가 영상 위치를 한 번도 알려주지 않음(교체한 영상이 이미 사라진 경우 — 오버레이가 허공에 남지 않게 되돌린다). 함께 **교체 중에 같은 페이지의 다른 영상(미리보기·광고·다음 화 예고)이 재생을 알려와도 지금 세션을 빼앗지 않게** 막았다 — 그 보고는 보류해 두었다가 지금 영상이 사라지거나 숨겨질 때 이어서 교체한다(영상 요소를 갈아끼우는 플레이어 대비). 한 번 재생에 실패한 스트림은 그 페이지에서 자동으로 다시 잡지 않는다(실패 안내가 반복되지 않게, 롱프레스 수동 교체는 여전히 가능)
- **우리 플레이어 HTTP 403 대응 — 사이트 플레이어가 보낸 헤더를 그대로 (v1.3.98)** — 영상이 다른 도메인의 플레이어 iframe 안에 있으면 CDN 은 그 iframe 주소를 Referer 로 기대하는데, 우리 플레이어는 최상위 페이지 주소를 보내 403 을 받고 사이트 플레이어로 되돌아갔다. 이제 사이트 플레이어가 그 스트림을 요청할 때 실제로 보낸 **Referer/Origin 을 붙잡아 우리 플레이어가 그대로** 보낸다(붙잡지 못하면 종전처럼 페이지 주소). 첫 프레임 전에 401/403/410 을 받으면 **Referer·Origin 없이 한 번 더** 시도하고 `[retry]` 안내를 띄운다. 최종 실패 안내에는 `ref=<보낸 Referer 의 도메인>` 과 `재시도함` 이 붙는다. 적용 범위는 인라인 교체뿐(전체화면·다운로드·Chromecast 는 종전 헤더)
- **주소가 `.m3u8`/`.mp4` 가 아니어도 스트림 잡기 — 응답 내용으로 감지 (v1.3.91, 실험)** — 지금까지는 요청 **주소**에 확장자가 있거나(`.m3u8`/`.mp4`/`.webm`), SNI 우회/프라이빗 DNS가 켜져 우리가 응답을 직접 받아본 경우의 `Content-Type` 으로만 스트림을 알아봤습니다. 그래서 주소가 `/v/e/<id>/c.html?token=…` 처럼 생긴 사이트에서는 영상이 멀쩡히 재생되는데도 "스트림 못 찾음" 이 떴습니다. 이제 페이지가 `fetch`/`XHR` 로 받아오는 응답의 **앞부분 512바이트**를 들여다봐 `#EXTM3U`(재생목록) · `ftyp`(mp4) · EBML(webm) 이면 주소와 무관하게 후보로 잡습니다. 설정 → **"스트림 내용 감지 (실험)"** 토글(기본 켬)로 끄고 켜며 비교할 수 있습니다. **한계:** 페이지가 로드를 끝낸 뒤 나가는 요청만 보이므로 영상을 한 번 다시 재생하거나 탐색해야 잡히는 경우가 있고, 조각(segment) 요청은 일부러 무시하며, 재생목록 자체를 JS 로 복호화해 `blob:` 으로 넘기는 사이트는 여전히 평문 주소가 존재하지 않아 잡을 수 없습니다
- **헤더 주입** — 페이지의 Referer / Cookie / User-Agent를 그대로 실어 보내 핫링크·서명 차단이 걸린 CDN도 재생
- **영상 다운로드 → 끊김 없이 보기 (v1.3.74)** — 통신 상태가 나빠 재생이 자꾸 멈출 때, 영상을 미리 받아두면 재생 중에는 네트워크를 아예 타지 않아 버퍼링이 없습니다. 영상을 길게 눌러 뜨는 메뉴의 **다운로드**, 또는 상단 ⋮ 메뉴의 **영상 다운로드**로 시작하고, ⋮ 메뉴 → **다운로드 목록**에서 진행률 확인·일시정지·재시도·삭제·재생. `.mp4` 같은 단일 파일뿐 아니라 **HLS(`.m3u8`)** — 조각 파일 수백 개로 쪼개진 스트림 — 도 통째로 받아 하나로 재생합니다. 받는 동안에는 알림에 진행률이 뜨고 브라우저를 다른 화면으로 옮겨도 계속 받습니다. 페이지의 Referer / Cookie / User-Agent를 요청마다 다시 실어 보내므로 보호된 CDN도 그대로 내려받습니다 (토큰이 걸린 스트림은 여전히 불가)
- **껐다 켜면 이어받기 (v1.3.76)** — 받던 도중 앱이 죽거나 재부팅돼도 **처음부터 다시 받지 않습니다.** 받아둔 조각과 대기열은 그대로 남아 있고, 앱을 다시 켜면 남은 다운로드가 자동으로 이어서 돕니다(진행률 알림도 다시 뜹니다). 일시정지해 둔 항목은 그대로 멈춰 있습니다. 다만 **앱을 열어야** 이어받기가 시작됩니다 — 백그라운드에서 알아서 재개하려면 부팅 권한이 필요해서 쓰지 않았습니다
- **받으면서 바로 보기 (v1.3.75)** — 다 받을 때까지 기다릴 필요가 없습니다. 영상 롱프레스 메뉴의 **받으면서 바로 보기**를 고르면 다운로드를 걸어놓고 **그 자리에서 재생**이 시작되고, 다운로드 목록에서도 받는 중인 항목을 탭하면 바로 볼 수 있습니다(목록의 버튼도 "지금 보기"와 "일시정지/이어받기"로 나뉘었습니다). 이미 받아둔 구간은 디스크에서 읽고 아직 안 받은 뒷부분만 네트워크로 받으므로, 보는 동안 다운로드는 계속 앞서 나가고 어느 시점부터는 네트워크를 거의 안 탑니다. **주의:** 회선이 아주 느리면 앞부분에서는 재생과 다운로드가 같은 구간을 두 번 받는 셈이라 오히려 더 끊길 수 있습니다 — 그럴 땐 다 받고 보는 쪽이 낫습니다
- **DRM 영상이 우리 브라우저에서만 검은 화면이던 문제 (v1.3.84)** — `WebChromeClient.onPermissionRequest` 가 없어 Widevine 요청이 기본 거부되고 있었다. Chrome/Opera 처럼 DRM 만 자동 허용한다. 자세한 내용은 아래 네트워크 섹션 v1.3.84 항목.
- **Chromecast 로 "지금 보내기" (v1.3.82)** — 예전엔 **기기를 연결하는 그 순간**에만 영상을 보냈습니다. 그런데 보통은 페이지를 열자마자 Cast 버튼부터 누르므로 그때는 아직 영상을 튼 적이 없어 보낼 것이 없고, 그 뒤에 영상을 재생해도 **아무것도 다시 보내주지 않아** 캐스트가 영영 안 되는 것처럼 보였습니다. 이제 ⋮ 메뉴 → **"Chromecast로 재생"**(영상 롱프레스 메뉴에도 있습니다)으로 **원할 때 보냅니다.** 순서는 기기 연결 → 영상 잠깐 재생 → 메뉴에서 보내기
- **확장자 없는 재생목록 주소 인식 + TV 쪽 실패를 코드로 표시 (v1.3.104)** — `…/stream/m3u8/<토큰>` 처럼 주소에 `.m3u8` 확장자 없이 **폴더 이름으로만** 재생목록임을 드러내는 사이트(plaver.pongping.top 등)의 영상을 이제 알아봅니다. 그래서 그런 사이트에서도 ▶ 플레이어로 재생 버튼·롱프레스 메뉴·다운로드·Chromecast 보내기가 동작합니다. 또 예전엔 TV 로 보낸 뒤 TV 가 재생에 실패해도 앱은 아무 말이 없었는데, 이제 TV 의 응답을 받아 **`[cast:load:…]` / `[cast:error:…]` / `[cast:idle:error]`** 코드와 짧은 원인(주소 접근 불가·재생목록 해석 실패 등)을 토스트로 보여줍니다. 보낼 때 토스트에는 보낸 영상의 호스트도 함께 나옵니다

- **재생이 안 될 때 이유를 알려줍니다 (v1.3.77)** — 다운로드한 영상을 눌렀는데 **플레이어는 뜨는데 재생이 시작되지 않던** 문제. 원인을 못 찾은 이유는 단순합니다 — 지금까지 이 플레이어는 **재생 실패를 어디에도 기록하지 않았습니다.** 실패하면 검은 화면에 컨트롤만 떠 있고 로그도 한 줄 안 남아, 밖에서 보면 "그냥 안 켜진다" 와 구분이 안 됐습니다. 이제 (1) 실패 사유(에러 코드 + 원인 체인)와 재생 상태 변화가 **설정 → 디버그 로그**에 남고, 화면에도 "재생 실패 (코드)" 가 뜹니다. (2) 그리고 다운로드본으로 재생하다 실패하면 **원본 주소로 한 번 자동 재시도**합니다 — 원인을 찾는 동안에도 영상은 볼 수 있게. 재시도로 재생되면 문제는 받아둔 파일 쪽, 재시도도 실패하면 스트림/네트워크 쪽입니다. **솔직히:** 이번 판은 원인을 **보이게** 만드는 것이지 고치는 것이 아닙니다 — 한 번 재현하고 디버그 로그를 보내주시면 그때 진짜 원인을 잡습니다

### 캐스트 / 미러링
- **Chromecast 송출** — 툴바 Cast 버튼으로 기기를 연결한 뒤, ⋮ 메뉴 → "Chromecast로 재생"(또는 영상 롱프레스 메뉴)으로 현재 페이지의 HLS(`.m3u8`) / MP4 / WebM 스트림을 리시버로 보냅니다. 주소에 확장자가 없어도 `/m3u8/` 폴더로 된 재생목록은 알아보고, TV 가 재생에 실패하면 `[cast:…]` 코드로 알려줍니다 (v1.3.104)
- **한계 — 오페라와는 방식이 근본적으로 다릅니다** — 오페라/크롬은 브라우저 엔진이 **탭 화면 자체를 인코딩해 전송**(탭 미러링)하므로 영상 주소가 아예 필요 없고 `blob:`/DRM 영상도 됩니다. 앱 내장 WebView 에는 그런 API 가 없어서 우리는 **영상 주소만 넘길 수 있고**, 크롬캐스트 기기가 그 주소를 **자기 회선으로 직접** 받아갑니다 — 우리 쿠키·Referer·User-Agent 가 하나도 안 실리므로 토큰/핫링크로 보호된 CDN 은 주소가 맞아도 403 을 돌려줍니다. 그런 사이트에서는 안드로이드 빠른설정의 **"화면 전송 / Smart View"** 로 화면 전체를 미러링하는 것이 현재 가장 가까운 대안입니다
- **VideoStreamSniffer** — `shouldInterceptRequest`에서 동영상 URL을 자동 캡처해 호스트별로 보관

### 네트워크 / 프라이버시
- **광고 차단** — 약 50개 광고/트래커 도메인 (Google Ads, DoubleClick, Taboola, Outbrain, Criteo, ExoClick 등) + URL 패턴(`/ads/`, `/pagead/`, `adsbygoogle` 등) 매칭으로 서브요청을 빈 204 응답으로 차단. CSS 셀렉터로 동일 도메인 광고 슬롯도 숨김. 설정에서 끌 수 있음.
- **쿠키 동의 배너 자동 거부** — OneTrust / Cookiebot / Quantcast / Didomi / Sourcepoint / TrustArc 등 주요 GDPR·CCPA 컨센트 플랫폼의 "모두 거부" 버튼을 자동 클릭, 실패 시 배너 자체를 CSS로 숨겨 콘텐츠 가림과 스크롤 락을 같이 해제. 설정에서 토글 가능.

- **프라이빗 DNS (DoH)** — DNS 조회를 ISP 대신 선택한 DNS-over-HTTPS 제공자(Cloudflare / Google / Quad9 / AdGuard, 또는 커스텀 URL)로 암호화. 켜면 SNI 우회와 별개로 모든 페이지에 적용되며, AdGuard 선택 시 DNS 단에서 광고·추적 도메인도 차단. RFC 8484 wire-format이라 임의의 DoH 엔드포인트(NextDNS 등) 지원. 설정에서 토글.
- **tvwiki308.com 사이트는 열리는데 영상만 "재연결중" — 수정 사다리 1/3: 격리를 서브도메인 계열 + 페이지 단위로 넓힘 (v1.3.88)** — v1.3.87 로 보안확인은 통과했지만 플레이어가 "재연결중" 만 반복한다는 보고. 지금까지 챌린지 호스트 격리(네이티브 전담)는 **정확히 그 호스트 하나**에만 걸려, 같은 사이트의 서브도메인(플레이어/CDN)과 그 페이지가 부르는 다른 호스트의 플레이어 iframe·스트림은 여전히 우리 OkHttp(SNI 우회 경로)·iframe 재요청을 탔다. - **웹툰 이미지 번호순 정렬 (v1.3.99)** — 회차 이미지가 뒤죽박죽 나오는 사이트(이미지 목록이 업로드 완료 순서로 들어 있는 경우)에서 상단 ⋮ 메뉴 → **이미지 번호순 정렬**을 누르면 파일명의 숫자(타임스탬프)로 이미지를 읽는 순서대로 다시 배치한다. 한 번 켜면 그 사이트는 기억되어 다음 회차부터 자동 정렬되고, 도메인 숫자가 바뀌어도(`blacktoon422` → `423`) 계속 적용된다. 같은 메뉴의 **이미지 원래 순서로**로 되돌리고 자동 정렬을 끌 수 있다. 파일명이 10자리 이상 숫자인 이미지만 대상이고, 보안 확인(캡차) 화면에서는 동작하지 않는다.
- **캡차("사람인지 확인") 흐름 보호** — Cloudflare Turnstile / hCaptcha / reCAPTCHA / DataDome 등 안티봇 챌린지 요청은 iframe 스크립트 주입도 SNI 우회 가로채기도 하지 않고 WebView 네이티브 로더에 그대로 맡긴다. 예전엔 챌린지 iframe을 앱이 다시 받아 CSP를 벗기고 스크립트를 끼워 넣었고, SNI 우회 시엔 챌린지 GET만 가로채고 검증 POST는 네이티브로 나가 커넥션이 갈라지는 바람에 체크를 해도 확인 화면만 무한 반복됐음. 통과 쿠키(`cf_clearance` 등)는 `CookieManager.flush()`로 디스크에 확정해 앱을 껐다 켜도 유지. 캡차가 감지되면 디버그 로그에 종류·주소·설정 상태가 남고, 같은 주소에서 3회 이상 반복되면 "루프 의심"으로 기록.
- **HTTP/HTTPS 프록시** — 인증 포함 외부 프록시 경유 (WebView 트래픽)
- **크래시 로깅** — `Thread.setDefaultUncaughtExceptionHandler` + `WebViewClient.onRenderProcessGone`으로 메인 프로세스/WebView 렌더러 충돌을 `filesDir/crashes/`에 영구 저장. 디버그 로그 화면에서 조회/복사.
- **인앱 디버그 로그** — `DebugLog`가 SNI 우회 / 광고 차단 / 캐스트 / 캡차 감지 이벤트 등을 메모리 링버퍼 + 화면에 표시

## 갤럭시 S24에 설치하기

### 1. GitHub Actions로 APK 빌드
- 이 저장소를 GitHub에 push하거나 `v1.x.x` 태그를 push하면 `.github/workflows/android.yml` 워크플로우가 자동 실행됩니다.
- GitHub 저장소 → **Releases** 탭 → 최신 릴리스의 `app-debug.apk` 다운로드 (태그 push 시 자동 첨부, 최신 3개만 유지)
- 또는 **Actions** 탭 → 워크플로우 실행 → **Artifacts** 섹션의 `player-browser-debug-apk`

### 2. S24에 설치
1. 다운로드한 `app-debug.apk`를 S24로 전송 (USB / 메신저 / 클라우드).
2. **설정 → 보안 및 개인정보 보호 → 출처를 알 수 없는 앱 설치** 에서 사용하는 파일 관리자(또는 브라우저)에 권한 허용.
3. 파일 관리자에서 APK 탭 → 설치.
4. 첫 실행 시 보안 경고가 뜨면 "그래도 설치" 선택.

> 디버그 빌드는 디버그 키로 서명됩니다. 정식 배포는 release 빌드 + 자체 키스토어가 필요합니다.

### 3. 인앱 업데이트
설치 후에는 메뉴 → "업데이트 확인"으로 새 버전을 받을 수 있습니다. 자동으로도 GitHub Releases를 폴링하므로 새 태그가 push되면 다이얼로그가 뜹니다 (자동 확인은 6시간에 한 번).

GitHub API는 로그인 없이 쓰면 IP당 시간당 60회 제한이 있고 모바일은 통신사가 IP를 공유하므로 가끔 `HTTP 403`이 날 수 있습니다. 그때는 API를 쓰지 않는 경로(릴리스 페이지 리다이렉트)로 자동 폴백하므로 업데이트는 그대로 진행됩니다.

다운로드된 APK는 앱이 `PackageInstaller` 세션으로 **직접** 설치합니다 — 파일을 시스템 "패키지 설치 관리자" 앱에 넘기지 않으므로 앱 선택 창이 뜨지 않고, 설치 실패 시 이유를 앱이 알려줍니다. 시스템 확인 창 자체는 Android 보안 정책이라 없앨 수 없지만, Android 12 이상에서 이 경로로 한 번 설치된 뒤부터는 확인 없이 바로 업데이트될 수 있습니다. (처음 한 번은 "알 수 없는 앱 설치" 권한 허용이 필요합니다.)

## 동영상 제스처 동작 원리

- `BrowserWebView`의 `onPageFinished`에서 `video_gestures.js`를 페이지에 주입.
- 페이지의 `<video>` 요소 위 터치 이벤트(`touchstart` / `touchmove` / `touchend`)를 가로채 손가락 개수·방향·시작 위치로 동작 분기.
- 네이티브 풀스크린에서는 `GestureCapturingFrame`이 raw 터치를 사이트(WebView)로 다시 흘려 사이트 자체 컨트롤·탭·네이티브 컨트롤 바가 동작하게 하고, 앱은 사이트가 제공하지 않는 **세로 밝기/볼륨 + 2손가락 영상 전환 + 1손가락 스와이프 ±10초**만 얹고, 그 피드백(음량/밝기 바, 시킹·전환 메시지)은 페이지가 아니라 앱이 직접 그리는 HUD 로 표시합니다(v1.3.42; HUD 와 스와이프 시킹은 v1.3.90). 풀세트 제스처(±10초 더블탭 등)가 필요하면 메뉴 → "플레이어로 재생"의 **내장 Media3 플레이어**를 사용하세요.
- 시킹/전환 시 화면 상단/측면에 토스트 또는 진행바 표시.
- iframe (cross-origin 포함) 내부 `<video>`도 `IframeScriptInjector`가 HTML 응답에 `<script>`를 prepend해 지원. 보안 확인으로 격리된 사이트는 재요청을 하지 않으므로 `ChildFrameGestureInjector`가 `addDocumentStartJavaScript`로 자식 프레임에 직접 주입(v1.3.105).

YouTube 등 자체 제스처가 강한 사이트는 일부 동작이 충돌할 수 있어, 일반 `<video>`를 노출하는 사이트에서 가장 잘 작동합니다.

## 광고 차단 동작 원리

- `BrowserWebView.shouldInterceptRequest`에서 가장 먼저 `AdBlocker.intercept()` 호출.
- 매칭 시 빈 `204 No Content` 응답 반환 → 광고 페이로드 다운로드 자체를 막아 트래픽/배터리/렌더링 시간 절약.
- 메인 프레임 요청은 절대 차단하지 않음 (실수로 광고 URL을 직접 입력했을 때 빈 페이지가 되는 사고 방지).
- `onPageFinished`에서 동일 도메인 광고 슬롯을 가리는 CSS를 한 번 inject.
- 광고 차단을 감지해 콘텐츠를 막는 사이트는 설정에서 토글로 즉시 끌 수 있음.

## 크래시 / 디버그

- 메인 프로세스 충돌 → `CrashRecorder`가 `filesDir/crashes/crash-{시각}.txt`로 스택트레이스 저장 (최대 20개 보관)
- WebView 렌더러 충돌 → `onRenderProcessGone`이 잡고 `true` 반환해 앱 살아남기 + 에러 페이지 + 토스트 + 기록
- 메뉴 → 설정 → 디버그 로그에서 충돌 목록과 풀 스택트레이스 조회 / 클립보드 복사 가능
- 디버그 로그는 `DebugLog` 링버퍼로 SNI 우회 / 광고 차단 / 캐스트 등 이벤트 실시간 표시
